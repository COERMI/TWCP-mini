# 运输影像归档

每次运输建立一份独立档案。司机核对车牌后按顺序拍照，总部按本趟运输查看照片和问题记录。

最新司机体验改动见[司机体验优化实施说明](docs/司机体验优化实施说明.md)：三步进度、开关门自动保存、管理员发微信卡片、取景提示及两版水印样例。新版主包已切换并通过开发者工具预览编译，聊天分享和相机仍待真机验收；水印候选未替换云端现用样式。

## 第一版约定的拍照流程

1. 总部创建本趟入口，司机确认车牌；车牌不符就联系工作人员重发。
2. 运输前依次拍：**货运单 → 货物码放 → 装好的车厢**，三项归档后提交基础资料。
3. 途中每次开门、关门均拍照，同一次开关门为一组，可以各拍多张。
4. 额外问题随时记录，可写文字、加照片。
5. 全部卸货后，司机明确确认“完成运输”；关门不会自动结束运输。

重复打开同一入口接续同一趟，不提供司机往次运输提交入口。已提交必需类别的最后一张照片，先补拍归档成功再移除。详细规则见[第一版实施基线](docs/V1_ACCEPTED_SCOPE.md)。

## 开发人员本机复现

以下命令在项目根目录执行；负责人日常不需要执行这些命令。

```powershell
npm ci --prefix admin
npm ci --prefix cloudfunctions/imagePipelineProbe
node --test "test/*.test.cjs"
npm run build --prefix admin
node scripts/preview-admin.cjs
```

本机总部地址：`http://127.0.0.1:4180/`。这个服务依赖本机已经登录的CloudBase CLI及原管理员登录，克隆仓库本身不会取得云端权限。二维码还依赖已安装、已登录且开启服务端口的微信开发者工具。不能把本机桥接直接作为公网服务。

根目录没有`package.json`，不要在根目录运行`npm install`或把旧`cloudbaserc.json`整批部署。云端部署须按[当前部署说明](docs/DEPLOYMENT.md)顶部说明及对应阶段报告逐项核对。
