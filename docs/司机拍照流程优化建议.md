# 司机拍照流程优化建议

依据 2026-11-21 提供的《26-27供应商开会内容(1).docx》及本次沟通编写。本文为产品设计建议，具体入口、拍摄清单和运输结束规则尚待原型验证。项目当前目标为司机拍照留档，供后续核查运输过程。

建议把“本次运输由谁建立和识别”交给发入口的人及系统，把司机操作集中在确认车辆、按提示拍照、确认货物是否全部送完。每趟运输使用独立拍照入口，重复打开始终回到同一趟。卸货点可以有多个，最后一次卸货后保留补传和补拍能力。

## 会议文件对照片的实际要求

正文的装货作业、卸货作业与 KPI 表“信息反馈管理—信息反馈”共同给出了以下拍摄内容。文件中的发货信息示例还列出多个卸货地点及顺序，因此一次卸货结束需要与整趟运输结束分别处理。

|现场节点|文件要求留存的内容|司机可以看到的提示|
|---|---|---|
|装货前|空车厢、清洁状况、预冷温度显示|“还没装货，拍车厢里面”“拍温度显示屏，数字要清楚”|
|装货中|蓝莓箱码放、不压箱、留风道；正文还要求撑杆、棉被、布帘等装载措施|“拍清货物怎么摆，固定杆和留出的空隙尽量拍全”|
|装货后|封车、车牌；正文要求装后打冷达到温度要求再拍照反馈|“拍关好的车门和车牌”“再拍一次温度显示屏”|
|卸货前|开门和温度显示|“开门前先拍车门和温度，开门后拍里面货物”|
|卸货中|开门、卸货过程、卸货环境|“拍卸货位置和正在卸的货；有破损，再拍近一点”|
|卸货后|卸后空车、签收单；破损、短少按文件要求在回单上签注|“拍卸完后的车厢”“拍签好字的单子，四个角和字都要清楚”|

多点卸货时，中途一站卸完可能还有余货，提示应为“拍卸完后的车厢和剩余货物”。最后一站才引导拍空厢。货运运单仍保留为识别本趟运输的重要照片，多份运单允许拍多张。

会议文件同时规定群聊反馈、温控报告、车辆材料、报表、对账和考核。当前拍照产品以照片和归属信息覆盖相关留档环节。接收方是否接受小程序查看代替群内发送，需要业务另行确认；现有群内反馈仍按实际约定执行。

温度照片应拍车辆仪表或温度计显示，字段明确标为仪表照片。天气服务返回的环境气温只可作辅助信息。总部据照片核对仪表读数，第一阶段可由人工查看。

## 每趟一个拍照入口

推荐由负责人或驻场人员在已有后台增加一个轻量入口“准备本趟拍照”，填写或确认已知车牌，附发货日期和一个司机能认出的装货地或目的地方向。发货批次已知时可填写，司机无需重复录入。系统生成独立档案及拍照邀请，再由工作人员在微信发给对应司机。

这项建议需要增加准备和发送邀请的能力。它只负责把照片归到指定运输，工作量需纳入下一版原型和接口评估。

司机点开后先看到醒目的车牌及本趟说明。

```text
粤B12345
今天这趟货 · 从××装货

[车牌对，开始拍照]
车牌不对，联系发链接的人
```

再次打开同一个入口直接进入本趟未完成的拍摄任务，首页持续显示车牌及识别信息。新的一趟由工作人员发新入口。打开旧入口显示旧趟状态，并提供“补这趟照片”和“找最新拍照入口”，避免旧入口自动变成新档案。

邀请应由服务端校验，并在领取后关联实际拍摄者身份。首次确认车牌只是操作确认，授权仍需服务端完成。转发到其他人时，使用者需要受控授权才能接续拍摄。司机换手机、换人或由驻场协助拍摄，工作人员可重新发接续邀请，记录实际上传者，原照片归属保持可追溯。

若暂时无法每趟准备邀请，可保留通用入口。首次填写车牌并进入拍照；有未结束运输时只提供“继续这趟拍照”和次要入口“换一趟新货”。创建新趟前显示上一趟日期、车牌、最近照片，再确认是否换货。通用入口要求司机多作一次判断，优先将其作为备用路径。

微信内采用小程序卡片还是其他入口，需按实际发布版本、账号能力和真机分享效果验证。本轮尝试访问微信分享官方文档时页面未能打开，本文将邀请视为待实现的产品方案，接口参数与外部链接能力留给技术试件核实。

## 开始和结束都使用现场事实

应记录几个互不替代的时间。

|时间或状态|含义和取得方式|
|---|---|
|档案准备时间|工作人员为本趟生成入口，系统记录|
|首次拍照时间|首次照片的设备时间与服务器接收时间分别记录|
|发车时间|第一阶段没有可靠来源时留空；现场照片和点按钮的时间按实际含义记录|
|司机确认全部送完时间|最后卸货后司机明确确认，记录操作者和服务器时间|
|资料齐全状态|根据应拍项目和已成功归档照片计算，可晚于送完时间|

司机开始拍摄即可建立本趟的照片记录。预冷、空厢和装货照片属于发车前的记录，因此页面无需要求先点“开始行程”才能拍。

司机每次卸货拍完，问一句“这车货还有下一站要送吗？”

```text
这车货还有下一站要送吗？

[还有，继续送]
[没有，这车货全部送完了]
先不确定，稍后再说
```

选择“还有”就保留运输进行状态，展示“本次照片已收，可以继续送货”。下一站重新进入卸货拍摄，照片与本次区分。

选择“没有”后，用一次确认承接“确认这车货已经全部送完？”确认后显示“你已确认送完”，同时列出剩余资料，例如“签收单还没拍”“2张正在上传”。后台保留“司机确认送完”和资料状态。资料齐全后可标“照片已收齐”，由总部核查内容是否清楚、符合要求。

忘记确认结束时，后台显示“尚未确认送完”，负责人核实后可代为确认并记录原因。误点结束时，允许“还要继续送”纠正，保留之前的操作记录。新趟建档与旧趟补传各有独立归属，操作新趟不会把旧队列里的照片挪过去。

系统可以提示长时间没有新照片，但时间间隔、跨天、GPS 到达某地、一次关门或上传签收单，均不足以自动判定最后一站完成。原图的拍摄时间和照片归属固定保存，补传只增加实际收到时间。

## 给司机的页面只突出当前动作

主页面建议设置三个现场入口“装货拍照”“卸货拍照”“有问题拍照”，页头保留车牌及本趟说明。进到一个入口后，每屏只突出一个拍摄任务，用示意图和一两句短句说明。

每张照片的正常路径为“点拍照 → 拍摄 → 看清了吗 → 用这张 → 下一项”。任务需要多个角度时再点“再拍一张”。一次卸货中的照片归在同一个现场记录里，系统内部继续保留开门、过程、关门等事件类型。再次卸货新开一组，返回已拍组可补拍。

上传期间以文字和图标区分“照片还在手机里”“正在上传”“原图已收到，水印处理中”“已保存”“需要重试”。退出时有未传照片则明确提示，恢复进入后优先回到待传项。水印失败保留原图并提供后台重做能力。

所有现场入口应有“大字提示”“听提示”“联系负责人”等低学习成本辅助方式。建议先用少量预录中文语音解释拍摄对象和成功状态，允许静音。是否需要方言版本由试点反馈决定。具体按钮尺寸和文字大小在小屏及大字体模式下走查。

拍摄提示应帮助获取有用画面，例如仪表数字、运单四角、货物全景和破损近景。缩略图上的数量只说明收到了照片，第一阶段由总部查看内容质量。

对于连相机拍摄都需要帮助的司机，可在出车前由驻场人员带着完成首次进入和第一张拍摄。助手协助上传时应记录拍摄者或上传者，不把协助记录自动写成司机本人操作。

## 与已确认顺序规则的衔接

当前行动文件和原型记载负责人确认“运单→货物→车厢依次解锁”。本次会议文件增加了装货前空厢和预冷拍摄，以及完整卸货清单，属于需要补充的产品规则。

建议原有三项基础记录继续保留其顺序引导，同时增加可独立进入的“装货前拍照”及“卸货拍照”。如现场尚未拿到运单，空厢和预冷照片仍应能及时采集。基础记录的齐全状态继续检查，司机可在拿到运单后补齐。

若后续决定统一为完整的现场顺序，应先在原型中验证“运单晚到、已经装完才收到入口、第一次使用时已到卸货地”三个场景，并明确批准新规则。对于已错过的现场，记录“当时未拍”和缺项状态，后续拍摄保存真实发生时刻。

此前确认的“已提交某类最后一张基础图先补拍成功再移除”可继续使用。资料移除应记录操作原因及时间。到货状态、资料齐全状态和照片删除限制分别校验。

## 下一批实施任务

先更新交互原型，覆盖本趟邀请入口、装货前照片、一次卸货多张照片、全部送完确认及待补资料展示。原型中的站次只表达已经发生的卸货记录，司机无需提前输入完整路线。工作人员已知的收货点可显示为识别辅助，未提供时用第几次卸货和照片时间定位。

让不熟练使用手机的人按以下场景实际操作，记录是否需要口头帮助及误点位置。

1. 收到入口后认出自己的车，并完成一张空厢照片。
2. 同一入口打开三次，始终回到同一趟。
3. 中途卸了一部分，正确选择还有下一站。
4. 最后一站送完，但签收单尚未取得，正确保留待补状态。
5. 一张照片断网重试，始终归属原趟、原次卸货且只记一次。
6. 第二天收到新趟入口，旧趟签收单仍能补回旧档案。
7. 运单尚未拿到，仍可拍转瞬即逝的装货前现场。
8. 不小心确认送完，能够纠正并继续拍照。

通过走查后再确定接口与数据变更。预计需要支持工作人员准备档案和邀请、每次卸货的分组、送完确认及纠正、资料缺项、补传队列固定归属。每项设计都以司机能完成拍照和总部能回看为验收依据。
