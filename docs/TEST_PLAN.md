# 测试计划（TEST_PLAN）

## 1. 功能场景测试

### 场景 A：正常运输
1. 创建运输档案，填写车牌号。
2. 上传货物照片、装箱完成照片、运单照片。
3. 上传 1 次开门照片、1 次关门照片。
4. 提交档案。
5. 后台检查档案完整性（事件齐全、照片关联正确）。

### 场景 B：多次卸货
1. 创建档案，上传基础照片。
2. 连续创建 3 次开门事件、3 次关门事件。
3. 检查：事件是否独立、序号是否正确（第1/2/3次）、照片是否关联到正确事件。

### 场景 C：提交后追加
1. 创建档案并完成基础拍照 → 提交。
2. 再次进入同一档案（通过 access_token）。
3. 追加新的开门照片。
4. 检查后台正常显示，且能区分初始/追加照片。

### 场景 D：同一车辆多次运输
1. 同一车牌创建两份不同档案。
2. 分别上传照片。
3. 检查照片是否被错误合并到同一档案。

### 场景 E：网络异常
1. 上传中断网。
2. 检查失败提示。
3. 恢复网络重新上传。
4. 检查是否重复创建照片或事件（幂等）。

### 场景 F：定位异常
1. 拒绝定位权限 → 检查提示。
2. 重新授权 → 检查定位恢复后能正常记录。

### 场景 G：天气接口异常
1. 模拟天气服务不可用。
2. 检查照片仍能上传。
3. 检查天气缺失状态正确（不冒充、不阻断）。

### 场景 H：数据查询
1. 后台按车牌号查询。
2. 按日期查询。
3. 查看档案详情。
4. 检查事件分类。
5. 检查照片原图与水印图均可访问。

## 2. 边界与异常用例

| 用例 | 预期 |
| --- | --- |
| 车牌号为空 | 提示填写，不创建档案 |
| 连续快速点击「开始记录运输」 | 只创建一份档案（防重复） |
| 连续快速点击拍照/上传 | 不产生重复事件/照片 |
| 上传失败后重试 | 不重复创建逻辑事件 |
| 未提交照片删除 | 仅删除本地待上传项，不影响已存档照片 |
| 已上传照片删除（如支持） | 保留操作日志/原状态，不静默替换 |
| access_token 错误/过期 | 拒绝访问对应档案 |
| 后台未登录访问 | 跳转登录 |
| 同一车牌多次运输 | 档案隔离，不混淆 |

## 3. 性能关注点

- 档案列表分页加载。
- 照片缩略图懒加载。
- 后台详情页照片较多时的加载体验。

## 4. 验收对应关系

测试场景与《任务书第十五节验收标准》一一对应：司机端 15 项、后台 10 项、数据 8 项。
