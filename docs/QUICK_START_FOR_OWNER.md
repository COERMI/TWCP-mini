# 当前测试版使用方法（2026-11-22）

2026-11-23 司机体验更新：新版三步进度、开关门自动保存、管理员选趟发卡片、取景提示和上传进度/耗时已接入源码，主项目已指向新版并通过微信开发者工具预览编译。两种水印候选样例已生成，尚未替换云端默认样式；真实定位天气未接入，分享和相机仍待手机验收。具体操作与限制见 `司机体验优化实施说明.md`。此前“根主项目仍指向旧包”的描述为历史状态。

当前已使用你提供的AppID和专用测试环境完成配置。不需要重新注册小程序、创建云环境或修改域名。

1. 在这台电脑打开总部页面 `http://127.0.0.1:4180/`，使用既有管理员账号登录。页面若已登录，直接操作。
2. 点右上角“新建本趟运输”，填车牌、发货日期和运输方向；批次可以不填。
3. 核对车牌后点“确认车牌，创建本趟”。每次运输都单独创建，不能沿用上趟运输。
4. 点“生成本趟测试二维码”，等待微信编译。保持开发者工具已登录且服务端口开启；生成失败时档案仍保留，重试不会新建一趟。
5. 用有测试权限的微信扫码，先核对车牌，再完成三项基础照片、每次开关门、问题记录和最后全部卸货确认。
6. 总部点“查看本趟”，按本次开关门分组查看照片，可切原图和水印图。司机新上传后点“刷新本趟状态”。

如果关闭了二维码窗口，从列表的“本趟入口”重新打开。此操作只适用于尚未被司机确认、未过期、未停用的入口；已经确认的司机继续使用原入口接续。车牌发错且司机尚未确认时，可点“车牌发错，停用此入口”，随后用正确车牌新建；旧档案保留。

**当前仍是测试预览，尚未发布给正式司机。** 公网后台和正式入口正在分批实施。负责人上一趟手机测试已收到“没有报错”反馈，并在云端核对到运输完成，无需为了这份记录重复测试同一趟。

如果本机页面未打开，由实施人员运行：

```powershell
node scripts/preview-admin.cjs
```

详细进度与未验证项见`STAGE7_ADMIN_VIEW.md`。费用、权限及发布以实际账户和单独验收为准；旧教程已移入本机私有备份，不再作为当前操作步骤。


## 常见情况

- 二维码过期或生成失败：从同一趟的“本趟入口”重试，不需要再建档。
- 司机已确认：由原司机用原入口继续，后台不会将它重新分配给另一人。
- 图片没显示：在本趟详情里点“刷新链接”，无需让司机重新拍摄。
- 页面提示未登录：使用既有管理员账号登录；不要把密码填写到文档或GitHub。
- 想换车牌：未确认时先停用错误入口，再用正确车牌新建。已确认的交接仍需受控处理，不能随意改旧档案。

遇到不能确定的提示，记录档案编号和操作步骤，交给实施人员处理即可。
