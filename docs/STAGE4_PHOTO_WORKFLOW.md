## 接口

仍调用 `transportV1`，身份只使用可信微信上下文。所有司机动作先核对本趟所有者，不接受请求里的 OPENID。读写失败按 `{success:false,code,message}` 返回。

|action|输入|行为|
|---|---|---|
|startEvent|record_id、request_id、kind，基础项另传type；问题可传note|固定基础事件复用；当前开关门组复用；新组事务分配序号|
|reservePhoto|record_id、request_id、event_id、type、capture_time|先保存待传记录与稳定上传路径；重复请求不新增照片|
|uploadTarget|record_id、photo_id|只签发所属照片的待传地址；已归档无需再上传；临时签名不写入幂等回执|
|processPhoto|record_id、photo_id，首次传file_id|归档原图、生成水印并事务更新数量；重试沿用同一原图|
|removePhoto|record_id、request_id、photo_id、reason|逻辑移除并保留文件、原因与审计；最后一张必需照片须先补拍成功|
|submitBase|record_id、request_id|核实三项就绪且无待处理照片，再进入运输中|
|finishDoor|record_id、request_id、event_id|开门、关门均已归档且该组没有待处理照片才保存；不自动结束运输|
|cancelDoor|record_id、request_id、event_id|只能取消当前没有有效照片和待处理照片的空组；保留序号和审计|
|saveIssue|record_id、request_id、event_id、note|更新文字说明，审计保留原说明|
|completeTrip|record_id、request_id、confirm_all_unloaded:true|至少一组完整开关门、无进行中组、无待处理照片，才可完成|
|reopenTrip|record_id、request_id、reason|纠正误点完成，保留前次完成时间和原因|
|getWorkflow|record_id、collection、cursor|每页50项；返回phase、revision、数量及下一页游标|
|photoLinks|record_id、photo_id|核对归属后签发原图/水印图链接；未归档和已移除拒绝|

写动作的请求号在发起前保存。同一请求号修改动作或内容会被拒绝，响应丢失后重试不重复计数。

## 数据、一致性与归档

新增 `transport_v1_events`、`transport_v1_photos`，创建时即指定 ADMINONLY，并查询核对。两集合的分页索引是 `record_id_then_id`，字段顺序 `record_id` → `_id`。首次脚本产生的反向索引 `record_id_cursor` 保留取证；当前查询使用前者。索引创建、实际字段顺序、权限及下载源码比对见 `deployment.json`。

原图先写入独立归档位置并固定SHA-256，再生成派生图。渲染沿用阶段3已验证的 Sharp、中文字体和运单扩展页脚，打包脚本复制规范源文件；并非复制原图冒充水印成功。

照片状态包括 `pending_upload`、`processing`、`upload_failed`、`watermark_failed`、`ready`，移除以 `removed_at` 单独记录。处理租约90秒，工作者持随机令牌；旧处理返回时无法覆盖已接续的新处理或重复增数。函数实际配置为 Nodejs20.19、1024MB、60秒。

必需类别保护包括后一步仍在上传的情况，避免前一步的最后一张被删后，后一步才完成。已保存开关门组也需先补拍成功再移除最后一张。取消空组不等于真实卸货，完成必须至少保留一组完整的开门和关门。

当前是客户端显式触发服务端处理，超时/断网后可重试；尚未部署无人值守后台任务或孤立文件清理。定位本批明确显示“定位未采集”，不补造地址或天气。手机拍摄时间是相机返回后记录的设备时间，不冒充经过校准的相机传感器时间。

## 存储权限修复及影响

实际发现：原 PRIVATE 配置下，开发者工具客户端仍能直接读取归档原图，不能据配置名称宣布私有访问验收通过。尝试自定义目录规则被套餐拒绝，未升级套餐；失败结果保存在私有工作目录。

最终采用全环境存储 ADMINONLY，随后重新读取配置确认；客户端上传改为服务器签发的 COS POST 策略：

- 精确绑定存储桶、单个待传对象键、私有ACL、文件元数据、1字节至20MB、十分钟期限。
- 使用平台临时服务角色签名；客户端没有签名密钥、管理员业务令牌或长期密钥。
- 每次重试可重新获取临时策略；手机草稿不持久化临时凭据。
- 原图及派生图由隔离服务工作线程创建，不在主函数中清除或修改司机身份。
- 只有 `photoLinks` 通过本趟所有者检查后才签发查看地址。此前已签发的链接仍可能在原有效期内可用，逻辑移除不承诺即时撤销旧链接。

**兼容影响：** 存储权限是环境级别的，旧版直接 `wx.cloud.uploadFile` 的测试页面和阶段3旧上传试件会受影响。后续统一使用新版签名上传。未删除旧文件、旧记录或旧云函数；旧业务函数本身的空令牌等问题仍须在后续兼容切换批次处理。

官方签名依据：腾讯云 COS POST Object 文档 `https://cloud.tencent.com/document/product/436/14690`；小程序直传域名配置见 `https://cloud.tencent.com/document/product/436/34929`。

## 手机联调页

源码 `tools/workflow-probe/`，是本批独立联调工程，尚未替换根目录的旧正式小程序。

- 沿用负责人已确认车牌的原TEST邀请，不重新绑定，也不混入自动化另建的测试运输。
- 三项依次解锁；每次开关门一组；可多图补拍、查看原图/水印图、填写移除原因。
- 问题支持文字、照片及追加说明。全部卸货明确确认，误点完成可填写原因纠正。
- 照片先保存本机文件和稳定请求号，再发起网络操作。响应丢失、授权过期和水印失败均保留草稿，归档成功或服务端确认移除后才清理本机副本。
- 刷新按revision校对完整分页，已移除照片不计入有效列表；手机尚未预留的本地草稿也会阻止提交与完成。
- `wx.uploadFile` 返回的是上传任务，本实现等待成功/失败回调；不能把任务对象当成上传成功响应。

最新预览编译成功，38216字节，大小及状态见 `phone-build.json`。二维码保存在私有目录，已提供负责人扫码验证整趟。此次因开发者工具自动化无法连接，明确由真机检查补足原生上传结果。
