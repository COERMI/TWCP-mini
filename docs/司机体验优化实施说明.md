# 司机体验优化实施说明

日期：2026-11-23（北京时间）。

本批按负责人确认的“便捷、简单、清晰明了顺畅”方案实施。源码完成不代表微信聊天分享、相机辅助框和不同手机已经验收，也没有正式发布小程序。

## 负责人能看到什么

- 运输前三项显示进度条，每次只展开当前任务。照片归档成功后自动进入下一项，三项齐全后点“开始运输”，不再重复弹窗。
- 运输中点“拍开门照片”直接进入相机；关门照片归档成功后自动保存同组，不会自动完成运输。保存中断保留继续保存按钮。
- 补拍、原图、水印图和移除放在“本趟照片记录 / 补拍”；问题反馈点开再填写，减少首页按钮。
- 上传显示实际上传百分比；后续显示“正在生成水印并归档”，这一阶段不虚构百分比。
- 拍摄页面用线框提示重要内容区域、底部建议留白区，不加灰色遮罩，辅助线不进入原照片。当前为取景参考，选定水印后还需依据真机预览与成片裁切核对位置，不能宣称精确匹配。
- 旧司机源码仍保留在根目录 `miniprogram/`；微信项目配置已切换至 `tools/workflow-probe/miniprogram/`，作为新版预览主包。这个目录名来自早期联调，当前不再需要把邀请写死在源码中。

## 怎样发给司机

1. 在电脑总部后台创建本趟运输。
2. 手机进入小程序，点“工作人员入口”，使用现有管理员账号登录。
3. 搜索车牌，选择待发送的运输，核对车牌、日期和说明。
4. 点“发给司机”，选择微信联系人并确认发送。
5. 司机点聊天卡片，核对车牌后拍照；再次点同一卡片接续同一趟。

管理员登录信息仅保留在当前页面内存，退出或关闭页面后需重新登录；不写进分享路径。固定分享封面不使用管理员列表截图。只有未领取、未过期、未停用入口可以恢复；分享后不会自动创建下一趟或查找最新车牌。

开发预览、体验版与正式版的接收者权限和实际微信分享仍需真机核验，不能把“生成了预览二维码”当成“所有司机都能接收卡片”。正式发布另行安排。

## 两种水印怎么选

当前云端仍用既有水印。新增两个独立候选样式，先给负责人比较，不自动替换归档图片：

- A：信息叠加在照片底部，接近参考图；照片太矮时自动改成追加栏，防止大面积遮挡。
- B：完整照片下方追加信息栏，尤其适合货运单细字。

两版都有车牌色块、大号时间、日期星期、天气温度、地点、照片类别、运输编号和照片编号。使用自己的“运输影像”标识，不复刻第三方品牌或声称已有防伪验证。

生成样例：`node scripts/preview-watermark-styles.cjs`。六张合成样例在 `docs/evidence/2026-11-23/watermark-candidates/`，图片按仓库规则留本机，源码和脱敏尺寸结果可以同步。天气、地点均明确为演示数据，不是真实采集；目前没有新增天气供应商、定位申请或付费资源。选定样式后再接入真实采集及失败提示。

## 怎样判断慢在哪里

手机每次上传后，本机保存最近一次照片的准备、授权、上传、水印归档及总耗时，键名为 `v1_last_photo_timing_运输内部编号`。仅保留数字和照片类型，不保存签名地址或上传凭据。

这些数字需要真实手机拍摄后才有意义；当前不能声称速度已经提升。仍保留原图、顺序解锁、归档失败重试和最后一张必需照片先补后删的规则。

## 文件用途

|文件位置|用途|
|---|---|
|`tools/workflow-probe/miniprogram/pages/trip/`|司机进度、拍照任务、补拍、问题和完成运输|
|`tools/workflow-probe/miniprogram/pages/capture/`|小程序相机及不写入照片的取景提示框|
|`tools/workflow-probe/miniprogram/pages/dispatch/`|管理员登录、选本趟、微信分享|
|`tools/workflow-probe/miniprogram/pages/entry/`|接收卡片邀请、确认车牌和接续|
|`tools/workflow-probe/miniprogram/assets/share-card.png`|不包含司机或管理员数据的固定分享封面|
|`tools/workflow-probe/miniprogram/lib/photo-queue.js`|本机保留原图、上传进度、耗时和重试|
|`cloudfunctions/imagePipelineProbe/styled-watermark.js`|两种候选水印渲染器，不影响现用默认渲染|
|`scripts/preview-watermark-styles.cjs`|使用合成图生成两种水印样例|
|`test/driver-experience.test.cjs`|检查分享不带管理员令牌、自动保存和入口行为|
|`test/watermark-candidates.test.cjs`|实际渲染两版水印并核对页脚版运单正文像素|

回退新版主包入口：将 `project.config.json` 的 `miniprogramRoot` 改回 `miniprogram/`。这只切换本地工程；旧包与当前收紧的存储权限不兼容，不能据此直接发布旧包。

## 后台排序补充（2026-11-23）

总部运输列表新增“排序”：可选择“创建时间最新优先”或“最近更新优先”。选择后立即查询并回到第一页；排序在云端对全部符合条件的记录执行，再分页，不是仅把当前页重新排列。相同时间按内部编号稳定排列。查看详情后返回或刷新页面会保留排序条件。

“创建日期”仍只筛选运输的建档日期，选择“最近更新优先”不会改变日期筛选含义。若要查看昨天建档、今天上传的运输，应清空创建日期范围。旧档案继续按创建时间排序，不开放缺少统一更新时间语义的排序。
