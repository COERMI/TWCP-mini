PRODUCT GUIDE / V1

一趟运输，一份影像档案。

让司机按顺序拍照，让管理人员按车、按趟找到记录。

2026 年 11 月 24 日 · 北京时间 测试实现版 · 尚未正式发布

司机：照着拍

先核对车牌，完成运输前三项；每次开关门留照片，卸货完毕再结束。

手机管理：随手发

独立管理入口用于新增运输、查询列表、选择本趟后分享司机卡片。

电脑管理：集中查

按车牌、编号和时间找运输，集中查看原图、水印图及过程记录。

一条完整业务流程

管理员建档→分享本趟卡片→司机确认车牌→运输前 3 项→每次开关门→全部卸货完成

同一辆车下次运输要另建一趟。司机重新打开原卡片时接续原趟，不必寻找历史入口，也不会自动切到“最新的一趟”。问题反馈可在现场另行记录。

当前产品用于照片采集和过程查询。它不自动证明照片真实、不代替调度或业务判断；定位、天气和全新水印样式尚未全部交付。
本文按当前源码与已有测试证据编写。流程图是说明示意，不是发布版截图。后续验收通过后应更新版本状态。

FOR DISPATCHERS / MOBILE

手机管理端：新增、查询、发给司机

本页说明的是已实现但待真机验收的手机管理流程。正式版本默认打开管理页；当前测试版本能否进入还取决于预览/体验权限。正式卡片需在平台发布条件满足后交付。

1打开固定管理入口并登录

打开管理卡片，进入“运输管理”。输入管理员账号和密码；登录过期后重新登录。管理入口与具体运输无关，可以留作常用入口。

2创建本趟运输

点“＋ 新增运输”，填车牌、发货日期、装货地 / 目的地说明，批次选填。核对后点“创建本趟运输”。每次运输单独创建，不能复用上一趟。

若提示“上次创建结果待确认”，点“重试并确认创建结果”。系统沿用原请求，避免网络中断造成重复建档。

3核对并分享司机卡片

找到对应运输，点“选择并发给司机”。核对车牌、日期和说明，再点“发给司机”，在微信中选择正确联系人并确认发送。

按钮接收者打开后使用场景
分享固定管理入口管理首页 / 登录交给管理人员，不携带管理员登录凭据
发给司机所选这一趟的车牌确认入口交给负责该趟的司机，必须核对车牌

查询已有运输

输入车牌或运输编号，点“查询运输”。可切“全部运输 / 待发给司机”，按“创建最新 / 更新最新”排序，使用上一页、下一页查找。

当前只支持为尚未被司机确认、未停用且有效的入口重新选择分享。已确认的司机从原卡片继续。详细查图、原图水印切换与纠正记录查看以电脑端为主。

暂不包含手机端完整照片管理、批量导出或多个管理员角色权限配置。
FOR DRIVERS

司机端：按提示拍，等成功再继续

1先确认是自己的车

打开管理员发来的本趟卡片，核对车牌与运输信息。车牌不对就点对应提示并联系管理员重发，不能为了继续拍照而确认错误车牌。

2按三步进度完成运输前照片

① 货运单→② 货物码放→③ 装好的车厢

拍清运单正文、货物摆放和整体装车情况。每一项等待上传、水印处理与归档成功，再进入下一项。取景边框只是提示，重要文字不要靠近底部水印区域。

三项齐全后点“开始运输”，进入途中记录。拍完不等于已经传好；出现待处理或失败提示时，先完成重试。

3每次开门、关门都拍

每次开门点“拍开门照片”，按现场要求拍摄；关门时拍对应关门照片。关门照片归档成功后，本次开关门记录自动保存。无论卸货还是其他原因，都要留本次记录。

4有问题就补充记录

问题反馈可填写文字并配照片。需要补拍时展开“本趟照片记录 / 补拍”，选择对应项目；基础项目最后一张有效照片需要先补拍成功，才能移除旧照片。

5全部卸货后完成运输

确认这趟全部卸货完毕，再执行完成运输。一次关门不会自动结束整趟；如仍有待上传内容，按页面提示先处理。

网络不好时保留当前微信及本机资料，恢复网络后从原卡片继续并重试。当前没有“退出微信也一定会自动上传”的保证，不要为重试重新创建一趟。
现场拍摄请在安全停靠、允许操作手机时进行。不要在驾驶中操作。
FOR OPERATIONS / DESKTOP

电脑管理端：找到运输，核对照片

入口与登录

目前使用实施电脑上的本机后台，由实施人员启动后打开。正式公网地址尚未交付，不能把本机地址发给其他设备当作正式入口。账号由负责人单独交接，不写在卡片或教程里。

运输列表

  1. 进入新版运输范围，通过车牌、运输编号、状态等条件查询。旧数据在旧记录范围内查看。
  2. “创建时间”旁的小箭头：按新建时间从新到旧显示。
  3. “最近更新时间”旁的小箭头：按最近发生更新的记录从新到旧显示。想找刚上传照片的运输时，用这个排序。
  4. 列表日期筛选按创建日期，不会因切换更新时间排序自动变成“上传日期筛选”。查不到旧趟的新上传时，先清空日期条件。
  5. 进入“查看本趟”；返回列表后保留原筛选及排序条件。

本趟详情

查看运输状态、基础资料提交时间、完成时间、有效照片数和待处理数。按运输前项目、每次开关门和问题记录核对照片。

操作作用
刷新本趟状态司机刚上传后，重新获取记录与处理状态。
查看 / 切换原图放大照片，切换原图和水印图；必要时用原图检查细字。
刷新链接图片临时访问链接失效时重新获取，不必要求司机重拍。
显示取消和移除记录查看历史纠正信息；“移除”不表示后台原文件已物理删除。

电脑建档与发错入口

也可在电脑端点“新建本趟运输”。当前电脑入口仍提供测试二维码；实际聊天卡片分享以手机管理端为目标。车牌发错且司机未确认时，停用错误入口，再用正确车牌建档。已经确认的运输不要随意重派，交给实施人员处理。

建议以运输编号核对同一趟，不只看车牌；同一辆车可以有多趟不同记录。
HELP & LIMITS

遇到这些情况怎么办

情况先这样处理
今天拍的照片在列表找不到确认新版范围，清空创建日期筛选，点更新时间小箭头，再按车牌 / 编号查找并刷新详情。
拍照上传慢区分“上传中”与“生成水印并归档”；不要连续重复拍同一项。记录手机网络、照片项目和等待时间供排查。正式发布不会天然消除处理等待。
手机中断或误关页面同一手机打开原卡片接续，查看待处理任务并重试；避免清除微信缓存或换手机后期待本地待上传照片自动出现。
二维码过期由实施人员重新生成测试预览；正式日常入口以小程序卡片为目标。二维码有效期和运输邀请有效期是不同问题。
照片打不开先刷新状态及图片链接。若持续失败，记录运输编号、照片项目和提示。
没有位置、天气当前未接入，属于待确定交付项，不能拿演示水印里的文字当真实采集。
时间是否准确拍摄时间取自手机，另记录服务器接收时间；水印按北京时间显示。设备时间异常需核查，不承诺防篡改认证。
换司机 / 误点完成联系管理员核对本趟编号，按受控纠正流程处理，不能把旧入口随意发给另一司机重新确认。

反馈问题时给三条信息

① 哪一趟运输编号；② 点了哪个按钮、在什么步骤；③ 页面提示及发生时间。可以补截图，但运单、司机邀请、账号和真实照片不要上传到公开代码仓库。

照片计划保存多久、到期是否导出、何时删除，需要公司确定。当前不能承诺“保存半年后自动清理”；逻辑移除也不会自动降低存储费用。
FIRST REPORT / ACCEPTANCE

第一次汇报：先讲价值，再讲边界

“这版主要把一趟运输的照片集中起来：管理人员先建档，司机按三项顺序拍照，途中每次开关门留记录，最后确认卸货完成。电脑端可以按车、按趟和更新时间查询。核心流程已在测试环境跑通，手机管理入口已开发，下一步做分享实测和正式上线准备。先用少量运输验证，再决定第二版增加哪些功能。”

建议 8 分钟演示顺序

  1. 1 分钟：讲清“一趟一档”和三个使用角色。
  2. 3 分钟：用专门演示趟展示车牌确认、三步拍照、开关门与完成。演示数据明确标注，避免影响业务记录。
  3. 2 分钟：电脑按更新时间找到同一趟，打开水印图和原图。
  4. 2 分钟：展示待验收清单、试运行安排和费用方案。未验证的分享功能用本说明讲解，不装作已现场通过。

请老板确定的四件事

  • 指定一位懂现场流程的验收人，确认正常一趟的照片数量及异常情况。
  • 确认首批试运行车辆、每天运输趟数和正式开始日期。
  • 确认照片保存口径：每张至少半年，还是产季结束后再保留一段时间。
  • 确认首版范围、开发费、运行费、维护方式及账户归属。

试运行验收单

  • 固定管理卡片打开登录；司机卡片打开正确车牌。
  • 三项按顺序解锁；每次开关门可查；问题反馈与完成运输正确。
  • 断网重试不重复建档；错误车牌与不该查看的运输被阻止。
  • 电脑找得到本趟全部照片，待处理数归零；水印清晰可读。
  • 公网访问、备份恢复、账单提醒和发布状态均有明确记录。
资料负责人：项目实施方。待业务验收人补充姓名与验收日期后形成最终交付记录。预算及报价另见本机商务草案。
