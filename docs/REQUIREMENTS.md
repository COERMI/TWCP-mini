# 需求说明（REQUIREMENTS）

> 本文是《运输过程影像采集与事件归档系统任务书 V1.0》的精简需求映射，作为开发依据。细节以任务书为准。

## 1. 司机端（微信小程序）

| 模块 | 需求 |
| --- | --- |
| 进入方式 | 微信分享入口（分享卡片 / 二维码），需验证合规入口方式 |
| 首次页面 | 「运输照片采集」；填写车牌号 → 点击「开始记录运输」 |
| 创建档案 | 校验车牌非空 + 宽松格式校验；生成全局唯一档案编号（如 TR2026120001）；记录创建时间；状态=进行中；生成 access_token；跳转采集页 |
| 采集主页面 | 显示档案编号 + 车牌号；固定节点按钮 + 动态事件按钮 + 已拍统计 + 「完成本次运输」 |
| 拍照引导（重点） | **向导式分步引导**：固定节点按「货运运单→货物照片→装货完成照片」**严格顺序锁定**（上一步未拍不可进下一步，可返回补拍）；开门关门为独立随时可拍入口，不占步骤 |
| 固定节点 | 按顺序：①货运运单 → ②货物照片 → ③装货完成照片；各支持多张、预览、删除未提交照片、重拍、上传反馈 |
| 动态事件 | 开门 / 关门；每次点击新建独立事件（第N次），不覆盖、不限次数、不强制配对 |
| 备注（新增） | 拍照/事件支持填写可选备注（如「第2次开门：中途卸货」），存入事件记录，后台可见 |
| 其他照片（可选） | 特殊场景额外照片，可填简短备注 |
| 拍照流程 | 调摄像头 → 预览 → 获取时间/定位 → 生成水印 → 上传原图 → 服务器生成水印图 → 保存关联 → 返回成功 |
| 上传可靠性 | 上传进度、失败重试、防重复提交、幂等、待上传队列（可选）、不把失败显示为成功 |
| 提交与追加 | 「完成本次运输」→ 状态=已提交；已提交后仍可继续追加事件（同一档案编号） |

## 2. 自动信息采集

| 信息 | 要求 |
| --- | --- |
| 时间 | 设备拍摄时间（如有）+ 系统记录时间 + 服务器接收时间；以服务器接收时间为标准，设备时间作辅助 |
| 日期/星期 | 由拍摄时间自动计算；统一使用北京时间（Asia/Shanghai, UTC+8），数据库存标准时间 |
| GPS | 申请定位权限，获取经纬度 + 精度 + 定位时间；逆地理编码为可读地址；失败提示可重试、不伪造、明确「定位未获取」 |
| 天气 | 由坐标 + 时间调用天气服务获取（优先历史天气）；失败不阻断上传、不冒充、记录获取状态 |
| 水印 | 服务器生成；统一样式；含车牌/时间/星期/地点/天气/档案编号/事件；原图与水印图分开保存 |

## 3. 后台（Web 管理）

| 模块 | 需求 |
| --- | --- |
| 登录 | 管理员账号 + 密码；未登录不可访问；可退出；账号不得硬编码在公开前端 |
| 档案列表 | 档案编号/车牌/创建时间/最近更新/照片数/事件数/状态/查看；按车牌、编号、日期、状态搜索 |
| 档案详情 | 基本信息区 + 事件列表区（按事件分类，不混排）+ 事件照片详情区 |
| 照片展示 | 缩略图 + 拍摄时间 + 服务器接收时间 + 定位 + 天气 + 车牌 + 档案编号 + 事件类型；可看大图与原图 |

## 4. 数据与安全要求

- 档案/事件/照片三类编号全局唯一；关联关系准确；原图与水印图均可访问。
- 对象存储保存文件，数据库只存 URL + 元数据；文件名不暴露隐私。
- 后台查看照片需鉴权或使用有效期安全链接；司机上传需校验 access_token。
- 敏感信息（密钥、密码）不提交公开仓库，使用环境变量。

## 5. 验收标准（摘要）

- 司机端：正常打开、填车牌、建档案、三类固定照片、重复开门/关门独立保存、自动时间/日期星期/定位/天气、水印、原图、上传状态、提交后追加。
- 后台：登录、全部档案、车牌搜索、日期筛选、单档案、按事件看照片、时间地点水印、原图、追加照片、档案间不混淆。
- 数据：三类编号唯一、关联准确、服务器接收时间、失败不显示成功、防重复。

## 6. UI/UX 原则

- 司机端：中文名称、大按钮、步骤少（≤3 步）、不展示技术术语/表格、单手可操作、反馈明确。
- 后台：以档案检索与事件归档为中心，照片始终可追溯到所属档案与事件，避免普通图片墙。
