# 运输前三项与每次开关门：当前原型

2026-11-21。依据用户在对话中明确确认的流程更新，只涉及本地原型。本文取代上一版装货／卸货／问题三个并列入口的验收口径；上一版记录仍保留用于追溯。

## 确认规则与实际页面

1. 后台准备每趟专属入口，司机核对车牌。入口始终绑定原档案；不按“最新”或同车牌自动跳趟。司机端取消往次入口列表、通用新建运输及“找最新入口”。
2. 车牌不符使用红色边框、浅红底的完整按钮，点击后明确提醒先别拍、联系发入口的负责人重新发送。
3. 运输前必须按货运单→货物码放→装好的车厢依次拍摄归档，再提交三项。途中开关门在基础提交后开放。
4. 每次开门、关门都拍，不区分卸货、检查或临时开门。同一次可以拍多张，开门和关门在一个编号组；保存后下一次独立编号。关门前要求本次开门照片归档。
5. 开门／关门必拍项没有“当时未拍”或跳过完成的入口。失败照片保留原身份、档案和分组，重试处理；本次还有待处理照片时不能保存为已结束。
6. 问题反馈随时可用，可单独写说明或拍全景、细节。说明附操作人及时间，总部可见；输入草稿会保留，点击“保存本次问题，返回本趟”也保存尚未单独提交的说明。
7. 所有开关门记录保存且照片处理完成后，由人点击“全部卸货完毕，完成运输”，二次确认结束本趟。照片齐全、关门、时间经过都不会自动结束。误点可记录原因纠正，保留原确认记录。
8. 运输前三项提交后收成简洁状态条，突出当前开门或关门操作；本趟照片和辅助功能折叠。空厢、温度等放在按需拍摄，不默认欠缺四项。
9. 已提交基础项与开关门必拍项的最后一张归档图，先补拍归档成功才可移除。旧版现场、照片、已确认状态不删除或强行合并；旧流程模型保留作兼容验证，当前界面不再提供新建旧式卸货流程。
