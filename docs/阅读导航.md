# 阅读导航：不懂代码也能找到需要的说明

更新日期：2026-11-22。

## 日常只用看这三份

1. `QUICK_START_FOR_OWNER.md`：负责人怎么建档、生成测试二维码、查图。只看顶部“当前测试版使用方法”即可。
2. `当前进度与下一步行动.md`：进展到哪一步，哪些还没测试；优先看顶部最新补充。
3. `文件用途说明.md`：逐个文件说明作用。你不用自己修改这些文件。

`README.md`是仓库首页，可以把它当作总目录。`GITHUB同步说明.md`解释代码怎么保存，以及为什么仓库里看不到密码、二维码和实拍照片。

## 想知道产品规则

|文件|用普通话说是什么|
|---|---|
|`V1_ACCEPTED_SCOPE.md`|你已经同意的第一版做法；较早建议有冲突时以这份为准|
|`司机拍照流程优化建议.md`|前期体验建议；并非其中每项都已纳入第一版|
|`PROTOTYPE_DOOR_FLOW_REVIEW.md`|最终主流程原型怎么验证的|
|`PROTOTYPE_WORKFLOW_REVIEW.md`、`PROTOTYPE_REVIEW.md`|较早原型的测试记录，保留来说明演变过程|
|`项目审查与重构方案.md`|为什么要重构、分几步做，以及每一步的检查要求|

## 想知道有没有做完、有何证据

|文件|看什么|
|---|---|
|`IMPLEMENTATION_STATUS.md`|各阶段状态表；区分已做、已测和待验收|
|`STAGE1_INVENTORY.md`|资产、云环境、源码和旧历史的盘点|
|`STAGE1_BACKUP_RESTORE.md`|备份和隔离恢复测了哪些，哪些没有测|
|`STAGE3_IMAGE_PROBE.md`|中文水印、方向、运单完整性等图片试验|
|`STAGE4_INVITATION_API.md`|本趟入口、车牌确认、身份绑定|
|`STAGE4_PHOTO_WORKFLOW.md`|照片归档、开关门、问题及完成运输|
|`STAGE7_ADMIN_VIEW.md`|总部查看、建档、入口停用及测试二维码|
|`evidence/`内文字摘要|每一批真正执行后的结果；截图、二维码及照片只留本机|

“本地测试通过”不等于“手机已经测过”，“测试环境可以用”不等于“已经正式发布”。报告会分别标明，不需要你从代码里猜。

## 主要交给开发人员看的资料

`DATABASE_SCHEMA.md`、`TECHNICAL_ARCHITECTURE.md`、`TEST_PLAN.md`、`DEPLOYMENT.md`说明数据、架构、测试及部署。较早文档中描述旧系统的段落仍保留，不应直接照着批量部署。

`PROJECT_OVERVIEW.md`、`REQUIREMENTS.md`、`PAGE_PROTOTYPES.md`、`DEVELOPMENT_PLAN.md`、`PROGRESS.md`属于前期背景；其中旧的“全部完成”、旧环境占位符或历史提交记录，不能取代当前实施记录。

## 遇到问题，怎样描述最有用

直接说明：在哪个页面、哪一趟档案、点了哪个按钮、看到了什么提示。可以描述“网络断开后点重试一直转圈”，不需要知道函数名。截图发给实施人员即可，含运单或二维码的截图不要发到公开GitHub。
