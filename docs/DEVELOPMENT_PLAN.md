# 开发计划（DEVELOPMENT_PLAN）

## 阶段总览

| 阶段 | 内容 | 关键交付 | 状态 |
| --- | --- | --- | --- |
| 一 | 项目调查与技术方案 | 技术选型、架构图、DB 初稿、开发计划、风险清单 | ✅ 已完成（待确认） |
| 二 | 原型与数据模型 | 页面原型、流程图、数据字段定稿、交互原型 | ⏳ 待开始 |
| 三 | 核心功能开发（小程序 + 后端） | 可运行的采集链路 | ⏳ 待开始 |
| 四 | 后台开发 | 登录 + 列表 + 详情 + 照片查看 | ⏳ 待开始 |
| 五 | 测试 | 场景 A–H 全通过 | ⏳ 待开始 |
| 六 | 上线交付 | 部署 + 审核 + 操作/部署手册 | ⏳ 待开始 |

## 阶段二：原型与数据模型

1. 司机端页面结构（首页填车牌 / 采集主页 / 拍照流程）。
2. 运输档案创建页面原型。
3. 照片采集页面原型（固定节点 + 动态事件 + 统计 + 完成）。
4. 开门/关门事件交互流程。
5. 后台档案列表 / 详情页原型。
6. 数据模型定稿 + 字段说明。
7. 核心业务流程图（创建档案 / 拍照上传 / 追加 / 后台检索）。

交付：页面原型、页面流程图、数据库字段说明、核心业务流程图。

## 阶段三：核心功能开发（顺序）

1. 项目基础结构（小程序 + cloudfunctions + 后台骨架）。
2. 云数据库集合与索引初始化。
3. 云函数：创建档案（含编号生成、access_token）。
4. 云函数：创建事件（固定 + 动态，序号自增）。
5. 司机端：车牌填写 + 创建档案。
6. 司机端：固定节点拍照（货物/装箱/运单）。
7. 司机端：开门/关门事件拍照（可重复）。
8. 司机端：多事件重复创建。
9. 云函数：照片上传（关联档案/事件，记录时间/定位/天气）。
10. 云函数：水印生成（原图 + 水印图分开保存）。
11. 云函数：档案提交 + 提交后追加。
12. 上传队列 / 重试 / 幂等 / 防重复。

## 阶段四：后台开发（顺序）

1. 管理员登录（账号密码 + 会话）。
2. 运输档案列表。
3. 档案搜索（车牌/编号/日期/状态）。
4. 档案详情（基本信息 + 事件列表 + 照片详情）。
5. 水印照片查看。
6. 原始照片查看。
7. 档案状态展示。

## 阶段五：测试（详见 TEST_PLAN.md）

场景 A 正常运输 / B 多次卸货 / C 提交后追加 / D 同车多次运输 / E 网络异常 / F 定位异常 / G 天气异常 / H 数据查询。

## 阶段六：上线交付

1. 配置正式数据库/云存储/小程序正式环境。
2. 配置后台管理员账号与安全规则。
3. 小程序审核与发布准备。
4. 后台部署。
5. 真实手机测试。
6. 编写《司机操作说明》《后台操作说明》《系统部署说明》。
7. 整理源码与环境配置说明。

## 需项目负责人提供的资料（关键，尽早准备）

| 资料 | 用途 | 是否必需 |
| --- | --- | --- |
| 微信小程序 AppID + 主体类型 | 司机端开发/发布 | 必需 |
| 云开发环境（若走 CloudBase） | 后端 | 必需（主推方案） |
| 和风天气免费 API Key（可选） | 天气水印 | 可选（无则降级） |
| 已备案域名 + HTTPS（若走自建后端） | 自建后端 | 仅自建方案需要 |
| GitHub 授权 | 代码备份 | 可选 |
| 后台管理员初始账号密码 | 后台登录 | 阶段四前提供 |

## 预计开发周期（估，受联调配合影响）

| 阶段 | 预计 |
| --- | --- |
| 阶段二（原型+数据模型） | 1–2 天 |
| 阶段三（核心功能） | 3–5 天 |
| 阶段四（后台） | 2–3 天 |
| 阶段五（测试） | 1–2 天 |
| 阶段六（上线） | 视备案/审核 1–3 周 |

> 注意：阶段六的微信审核与（若自建后端）ICP 备案时长不在代码开发控制范围内，需提前并行启动。
