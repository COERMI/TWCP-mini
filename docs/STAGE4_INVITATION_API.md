## 接口约定

所有请求调用 `transportV1`，通过 `action` 区分。成功返回 `{success:true,data,version}`，失败返回 `{success:false,code,message,version}`。不得在客户端传入身份作为授权依据。

|action|调用者与输入|结果|
|---|---|---|
|prepare|管理员 `token`；`request_id`、`plate_number`、`ship_date`、`description`、可选 `batch`|本趟摘要、专属 `invite`、未领取有效期|
|preview|可信微信身份；`invite`|未领取时仅车牌/日期/方向；已领取且身份一致时返回本趟摘要|
|claim|可信微信身份；`invite`、`request_id`、与后台完全相同的 `confirm_plate`|绑定当前微信身份并进入 `preparing`，重复请求不重复绑定|
|get|可信微信身份；`record_id`|仅所有者可读取本趟摘要|
|adminGet|管理员 `token`、`record_id`|本趟摘要及是否已领取，不返回司机原始标识|
|revoke|管理员 `token`、`invite`|幂等撤销尚未领取的入口；已领取拒绝简单撤销|

- `request_id` 为12—80位字母、数字、下划线或短横线。客户端发起动作前保存，网络重试复用。
- `prepare` 同一管理员+请求号确定同一档案；改说明/车牌/日期后继续用旧请求号会返回 `REQUEST_CONFLICT`，不能悄悄新建。
- 一次事务写入计数器、档案、入口哈希和审计。没有随机降级编号；事务失败应重试同一请求。
- 新版编号使用月计数器与六位序号，独立命名空间。旧档案不重编号；未来统一新旧查询前仍需核验跨版本显示编号冲突，不得仅凭显示编号关联照片。
- 同车牌可以有多趟，身份和照片归属必须依赖档案内部ID，不以车牌查“最新”。
- 入口以签名能力值发给司机，数据库只存哈希；服务端盐和密钥不得进入客户端。创建请求重试可重构同一入口。
- 未领取入口有效期默认7天。已领取的同一司机可以继续接续原趟，避免长途运输因入口领取期限中断。不同司机不能读取已领取入口。
- 确认车牌是一次领取动作，不是微信实名认证。入口应由后台发给正确司机；受控换绑、协助者接续在后续批次实现，当前不做静默换绑。
- 管理员兼容现有 HMAC token 签名格式，但强制合法 `sub/iat/exp`、未过期、最长7天。未配置或缺有效期默认拒绝。未复制管理员密码到新函数。

## 数据与权限

本批新增5个集合：

|集合|主要键与用途|
|---|---|
|transport_v1_records|确定性 `_id`；单趟摘要、所有者、状态、revision|
|transport_v1_invites|入口哈希 `_id`；所属档案、领取及撤销时间|
|transport_v1_requests|动作+身份+请求哈希 `_id`；领取幂等|
|transport_v1_audit|确定性动作ID；建档/领取/撤销审计|
|transport_v1_counters|月份 `_id`；事务分配档案序号|

创建时即指定 ADMINONLY，随后通过 DescribeDatabaseACL 核对5项均为 ADMINONLY。客户端只调用函数，不直接读写这些集合。当前只按主键访问，主键唯一索引满足本批用途；列表、事件和照片查询的索引以后随相应接口增加。

微信身份仅来自 `getWXContext()`。实际 CLI 调用的上下文不包含 ENV，首次验证因此被环境门禁拒绝；修复为仅从 SDK 上下文或平台提供的 `TCB_ENV/SCF_NAMESPACE` 取得环境，绝不从请求取身份或环境。已补包装器测试。

数据库初始化使用 `throwOnNotFound:false`，不存在文档返回空；数据库故障不冒充“不存在”。SDK提供事务冲突重试，回调不发送消息、生成外部文件或执行其他外部副作用。

## 手机入口验证

`tools/invitation-probe/` 是本批独立技术试件，包含车牌确认、红色车牌不符提示及当前档案重新读取。只连接云端TEST运输，不替代正式司机拍照页面。

运行 `node scripts/prepare-invitation-phone.cjs` 将 `driver-target.private.json` 生成到私有手机工程中，包内仅含本趟入口，绝不含管理员token。通过开发者工具 CLI preview 编译及生成私有目录的 `invitation-preview.png`。初次WXML编译因表达式中使用HTML实体 `&amp;&amp;` 失败，修复为WXML的 `&&` 后重试；以实际preview成功为编译证据。

负责人手机扫码后确认TEST车牌，点“重新读取本趟运输”，再退出重新扫码；预期仍显示相同编号且不重复确认。若转给另一位测试者，应提示已关联其他拍摄者。未经实际反馈，不登记真机绑定或双司机拒绝通过。

## 部署与回退

私有工作目录：`C:\Users\user\AppData\Local\Codex\transport-v1-20261122`。

1. 从测试环境读取现有 `adminLogin` 配置到该目录的 `admin-config.private.json`，不输出配置内容。
2. 运行 `node scripts/prepare-transport-v1.cjs`，复用现有管理员签名校验参数，另生成并保留独立入口签发密钥。不能在有有效入口时随意更换该密钥。
3. 建立上述5个新集合，创建参数指定 ADMINONLY，再读取核验。严禁用旧业务集合替代本批命名空间。
4. 首次部署指定 Nodejs20.19、私有函数目录；后续以 `tcb fn code update transportV1` 更新。此函数的带密钥清单不写入仓库根部署文件。
5. 等待函数实际 Active，再执行 `node scripts/check-transport-v1-cloud.cjs`。每次运行产生3条TEST运输；它不是生产环境验证脚本。

回退：正式页面尚未接入新版接口，可停止调用新函数；保留新增集合与审计，不回写或删除旧数据。后续接入时必须明确区分新版 `schema_version:1` 与旧档案，旧 token 不自动获得新档案权限。旧版读取/上传接口的空令牌等缺口尚未因本批新增函数修复，仍需后续兼容读取与切换验证。
