## 实现

- `cloudfunctions/imagePipelineProbe/`：图片处理源代码，Sharp 0.33.5、wx-server-sdk 2.6.3、打包的中文字体。
- 云端新试件 `imagePipelineV1Probe` 使用 Nodejs20.19、1024MB、60秒，仅部署于已获授权的专用测试环境。
- 48小时随机票据、环境检查、请求路径检查；无 HTTP 公开入口，不读写业务集合。
- 原图先归档，水印失败返回 `watermark_failed`，不将复制原图当成功水印。
- 运单保持原正文尺寸，在底部追加水印；其他照片按 EXIF 转正并限制长边，保留独立原图。
- 未采集位置及天气时如实显示；拍摄时间缺失时明确标注服务器收到时间。
- `tools/image-probe/` 是独立手机试件模板，提供实拍、确认、原图上传、失败重试及两图预览。其本地保存不等同于正式应用离线队列。

## 实测发现与修复

1. 原 Node18.15 无法加载 Sharp 0.33.5；配置更新命令成功并不代表实际运行时改变，另建 Node20.19 试件。
2. 云端自动安装出现 Linux 原生库缺失；显式增加依赖后仍出现异步 UpdateFailed。不能把命令退出0认定为部署成功。
3. 改为本地依赖随包上传，额外打包精确版本的 Linux x64 Sharp 和 libvips，关闭云端安装。代码更新后查询实际 Active 再调用。
4. 初始 `imagePipelineProbe` 旧试件仍保留取证；不用于后续手机预览。

## 复现

1. 在源试件目录安装 npm 依赖。
2. 运行 `node scripts/prepare-stage3-probe.cjs`，生成源码目录外的私有配置及手机工程。
3. 将 `npm pack @img/sharp-linux-x64@0.33.5` 和 `npm pack @img/sharp-libvips-linux-x64@1.0.4` 生成的包保存到私有试件目录。
4. 运行 `node scripts/bundle-stage3-probe.cjs`，准备完整部署依赖。再次运行 prepare 后必须重新 bundle。
5. 已有函数用 `tcb fn code update imagePipelineV1Probe`，传私有目录为 cwd、其 functions/imagePipelineV1Probe 为 dir。首次创建需明确 Nodejs20.19。
6. 等待实际函数状态 Active，再运行 `node scripts/check-stage3-cloud.cjs`。脚本将完整响应仅存私有目录，仓库中只保存合成图片和脱敏结果。
